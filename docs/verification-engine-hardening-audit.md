# Verification engine hardening audit

Audit scope: generic checker, evidence, result, and pipeline code in `src/seclab`; no GUI behavior or Smart-EV-specific logic was added. Checker semantics and the Task 3B/3C benchmark catalog/contract were left unchanged.

## Checker lifecycles

| Checker | Input → execution | Raw outcome → classification | Result and retained evidence | Traceability |
|---|---|---|---|---|
| CTL | Normalized explicit-state specification/model and formula → finite Kripke model checker | Holds at all initial states → PASS; counterexample → FAIL; invalid formula/model input → SPEC_ERROR; checker exception → TOOL_ERROR | Formula, initial states, witness/counterexample or error artifact | Result evidence IDs resolve in RunManifest; result trace entry carries checker, scope, stage inputs, artifact hashes, and run ID |
| BMC | Explicit graph, bad proposition, bound, timeout → encoded SMT query and solver | SAT with validated trace → FAIL; UNSAT through completeness threshold → PASS; bounded incomplete UNSAT/UNKNOWN/timeout → INCONCLUSIVE; backend/decode error → TOOL_ERROR | Query, solver outcome/raw output, completeness analysis, trace when SAT | Query and result evidence IDs plus manifest result trace; stage inputs include specification/model references |
| SMT | Specification domains/constraints, expression, query intent, timeout → validated encoding and backend | Violation-search SAT → FAIL; UNSAT → PASS within encoded finite scope; UNKNOWN/timeout or non-verdict query intent → INCONCLUSIVE; backend error → TOOL_ERROR; invalid/unsupported expression → SPEC_ERROR | Normalized query, backend outcome/raw output, model/counterexample where present | Result evidence IDs and hashes resolve from manifest; result trace includes specification-stage inputs and run ID |
| Static | Discovered source files, selected analyzer/configuration, timeout → tool process/parser | Findings and clean scans both remain INCONCLUSIVE; timeout → INCONCLUSIVE; missing tool/process error → TOOL_ERROR | Command metadata, raw output, normalized findings and source locations when available | Source hashes are attached in result trace; result evidence refs carry hashes |
| Memory | Source files, compiler/runtime, sanitizer instrumentation and execution → ASan/UBSan/LeakSanitizer | Recognized violation → FAIL; clean supported instrumented run → scoped PASS for no sanitizer finding in that execution; timeout/runtime unknown → INCONCLUSIVE; tool/build errors stay separate | Build/process records, raw sanitizer output, normalized findings, capability limitations | Source hashes and evidence refs are joined to results in the run manifest |
| Dynamic | Declared testcase/input, source or executable, explicit oracle and timeout → build/process/oracle evaluation | Oracle satisfied → PASS; oracle violated → FAIL; timeout/crash without decisive oracle → INCONCLUSIVE; compile failure → BUILD_ERROR; tool/runner error → TOOL_ERROR | Testcase, source integrity, process stdout/stderr/exit, observation and oracle records | Per-test result points to evidence IDs; isolated runner exceptions now persist diagnostic evidence and a result record |
| Coverage | Source files, explicit test cases, backend → instrumented executions and counter collection | Coverage percentages are measurements only; no safety PASS/FAIL. Missing data → INCONCLUSIVE; infrastructure/backend failure → TOOL_ERROR; build failure → BUILD_ERROR | Backend config/raw counters/normalized report; setup/collection errors now have diagnostic evidence | Stage and result trace point to artifact hashes and source hashes; measurement remains separate from property verdicts |
| Fuzzing | Test template, seed/configuration/source, bounded campaign → generated cases, executions, optional coverage feedback | Scoped oracle/sanitizer failure or asserted crash → FAIL; no finding, timeout, or unknown → INCONCLUSIVE; campaign infrastructure failure → TOOL_ERROR | Seed, budget, strategy, campaign/failure records, raw process evidence as applicable; campaigns unable to start now persist reason/config evidence | Verification results include campaign evidence IDs; manifest adds run ID, source hashes, and artifact hashes |

## Shared outcome mapping

`PASS` and `FAIL` require a checker-specific property, declared oracle, or scoped built-in sanitizer check to have been evaluated. `INCONCLUSIVE` covers timeout, UNKNOWN, incomplete bounds, missing observations, unsupported capability, and no finding in a bounded fuzz campaign. `TOOL_ERROR` is infrastructure/tool failure; `BUILD_ERROR` is a failed SUT/harness build; `SPEC_ERROR` is invalid input. Pipeline lifecycle uses `StageStatus.SKIPPED` with a reason when a stage does not run. A `VerificationResult` that explicitly did not run uses `NOT_RUN`.

Compatibility limitation: `VerificationStatus` does not currently define distinct `UNSUPPORTED` or `SKIPPED` result values. Unsupported checker capabilities retain a safe nonbinary `INCONCLUSIVE` or `TOOL_ERROR` status and a reason code/limitation; stage skips use `StageStatus.SKIPPED`. No unsupported or skipped path is promoted to PASS or FAIL. Adding new serialized status values would be a separate results-contract migration.

## Evidence, run identity, and pipeline

Run manifests resolve every result evidence ID to an `Evidence` record containing path, producer, type, and SHA-256. The report verifies workspace containment and hashes before manifest creation; report and final manifest artifacts are also checked after writing. The manifest is written once through `ArtifactStore` and is not modified afterward. It includes the report artifact reference. `metadata.result_traceability` joins each result ID to run ID, checker/stage, scope, stage input references, applicable source hashes, and complete evidence records with artifact hashes. The manifest does not self-reference; its path is the report's manifest entry point.

Stage graph construction rejects cycles. Stage failures produce a scoped TOOL_ERROR result and error artifact when persistence is available; independently selected checker stages continue unless a declared dependency failed or skipped. CTL/BMC/SMT isolate property errors; static and memory isolate analyzer errors; dynamic tests isolate testcase runner exceptions. Coverage remains measurement-only, and coverage-guided fuzzing alone treats coverage feedback as required.

## Fixes and remaining limits

This hardening pass fixed manifest hash invalidation caused by a post-write direct overwrite, cycle acceptance in stage graph validation, missing evidence on per-test dynamic runner exceptions, missing CTL error-evidence linkage, and missing diagnostic evidence for coverage/fuzz setup failures. Regression tests cover each fix.

The audit and tests establish contract behavior on exercised paths, not general checker soundness or completeness. External tools can be unavailable or differ by platform; sanitizer PASS is scoped to one instrumented execution, static clean results remain inconclusive, coverage is not a safety verdict, and fuzz no-finding remains bounded/inconclusive. No overall project verdict is computed.
